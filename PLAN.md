# Plan: Agentic Fraud Investigation on TigerGraph (HHGOA) — 6–7 hour build
_Locked via grill-with-docs — by Claude + LO. Terms per CONTEXT.md. Revised after Codex Rounds 1–2 (see PLAN-REVIEW-LOG.md)._

## Goal
Ship an agent that investigates each of the 20 case-pack triggers/cases against a TigerGraph graph + vector store, decides pattern / verdict / exposure, recommends policy-compliant next-best-actions with approval routes (initial and final), **drafts** a SAR (with a `FILE_REPORT` recommendation + route — never files externally) when policy requires, writes the case back to the graph as memory, and emits one schema-correct `<case_id>.json` per case in `cases/`. On the same Gemini 2.5 Flash model we run three isolated pipelines — Plain RAG (P1), GraphRAG (P2), Agentic GraphRAG (P3) — and report the relative lift plus per-case token/tool/latency cost on a **leak-free labeled eval set** — our headline Innovation result. The agent also makes its evidence choices explicit — ranking candidate evidence by expected decision impact before requesting (**evidence-value reasoning**) and, as a **stretch**, recording each recommended action's projected effect (**counterfactual**). P3 is the required deliverable and is built first.

## Mandatory per the spec (PDF "Required components" + "Submissions") — all in scope
- **TigerGraph (Savanna/CE) for BOTH graph AND vector** storage/retrieval — no external vector DB; embeddings are stored/queried inside TigerGraph. Savanna chosen; enable auto-stop/auto-start.
- **GSQL + graph algorithms** for traversal / pattern detection / relationship analysis.
- **TigerGraph MCP** exposes the graph to the agent — a **required** component and the primary, demonstrated integration (direct GSQL is only an internal fallback behind the same interface — see Risks). We do not ship a submission that bypasses MCP.
- **GraphRAG** grounds the agent (connected graph evidence + policy/typology docs), passed as context, not raw data.
- **A user interface** (analyst dashboard) — required and not fully cuttable (demo quality = 10%; minimum = a working read-only viewer).
- **One answer file per case**: the case (record / evidence / findings / decisions / actions) + **written to the graph** + **SAR when policy requires** + **NBA & approval route recorded both before and after** evidence requests.
- Framework (PydanticAI) and LLM (Gemini Flash) are the PDF's **free-choice** items — our picks, justified in the ADRs.
- **Innovation (15%) is a hybrid**: (a) the quantified three-pipeline **P1→P2→P3 relative-lift + token-efficiency** table is the guaranteed, measurable headline; (b) the agent's **evidence-value reasoning** — it ranks candidate evidence by expected decision impact before requesting (surfaced from behavior the spec already requires) — is the narrative; (c) a **counterfactual action projection** (each NBA's projected averted-exposure vs. friction tradeoff) is a **stretch**, built only if ahead of schedule. **P3 + its outputs remain the mandatory deliverable**; all three innovation layers sit on top of the single required agent.

## Approach (time-boxed, with cut-lines)
0. **Smoke test + adapter + pins (~0:00–0:30).** Prove the stack end to end on one case: Savanna reachable, a tiny GSQL load, a vector top-K query, a Gemini Flash call, a structured (Pydantic) output, one tool round-trip. Build the thin **graph-client adapter interface** now so MCP and direct-GSQL are drop-in equivalents (same signatures/return shapes). **Pin reproducibility**: exact Gemini model ID + generation params (temp, max tokens) + retry policy + fixed evaluation order. Any red → fall back early (Community Edition / direct GSQL) while it's cheap.
1. **Data + graph (~0:30–1:30).** Schema = README vertices/edges (Customer, Card, Transaction, DeviceProfile, EmailDomain, BillingRegion, ClosedCase) + a `Case` vertex for write-back. `CONNECTED_TO` carries the **shared-key type + value AND a time window** (device/recipient-email co-occurrence, not lifetime) with supporting transaction refs; the `Case` links its trigger transaction / card / customer, evidence/NBA/SAR stored as Case properties. Load **time-local targeted closures around every scored entity — both the 20 exam cases (Nov–Dec) and the held-out eval closed cases (Jul–Oct)** per [[0004-load-targeted-subgraph-prune-columns]], with explicit time/hop bounds (V-columns pruned; C/D/M + named identity kept; any V feature reachable via the `transaction_features` tool, Step 4). Verify one case by hand.
2. **Vector store (~1:30–2:00).** Embed with all-MiniLM-L6-v2 (384-dim, local, free), chunk ~1000/200: Fraud Policy, the five patterns, closed-case narratives, 2–3 key FinCEN SAR docs. **Split closed cases into memory-seed vs held-out eval BEFORE indexing.** During eval, held-out cases are exposed only as *unlabeled raw transaction context*: excluded from the vector index, from the `ClosedCase` graph case-memory, and from `similar_closed_cases`, along with near-duplicates; no outcome/pattern/verdict/analyst-note text of a held-out case reaches any pipeline. Store in TigerGraph vector search; cosine top-K.
3. **Shared lib + schema/validators (~2:00–2:30).** Model client (Gemini Flash) with **harness-side token/latency metering that wraps every model call incl. retries** (the `tokens`/`tool_calls`/`latency_s` fields are populated from the harness, never model self-report). Graph tools behind the Step-0 adapter as PydanticAI tools. **Freeze one strict answer schema, field-for-field from the README** (Pydantic; `<case_id>.json` filename binding; **the emitted file matches the README exactly — "missing fields score zero for that part"**). Top level: `case_id`, `case`, `evidence_requests[]{type∈(customer_validation|step_up_auth|analyst_info), asked_after_step:int, assumed_response:str}`, `next_best_actions`, `sar`, `stop_reason`, `tool_calls:int`, `tokens:int`, `latency_s:number`. `case`: `status∈(open|closed_fraud|closed_legitimate|escalated)`, `verdict∈(fraud|legitimate|uncertain)`, `fraud_probability`, `pattern`, `pattern_description` (required iff `pattern=undocumented`, else `""`), `affected_txn_ids[]`, `first_suspicious_txn_id`, `connected_card_ids[]`, `connected_device_profiles[]`, `exposure_usd`, `evidence[]{claim, source∈(graph|document|customer|external), ref, entity_ids[]}`, `similar_prior_cases[]`, `summary`, `written_to_graph:bool`, `graph_case_id`. `next_best_actions{initial[], final[], what_changed}` with each action `{action, route∈(auto|L1|L2), reason(cites rule)}`. `sar{file:bool, reason, narrative, subjects[], total_amount_usd, activity_dates[2]}` — always present; when `file=false` → `narrative=""`, `subjects=[]`, `total_amount_usd=0`, `activity_dates=[]`. Pin the **14-action enum + the exposure-conditional route matrix** (`BLOCK_CARD` L1 ≤ $2,500 / L2 > $2,500; `BLOCK_ALL_CARDS` & `FILE_REPORT` always L2) and the **SAR predicate** (confirmed/strongly-suspected **AND** (exposure > $1,000 ∨ shared device/region/other-customer fraud ∨ coordinated/undocumented)) from README §1–3a. **Innovation extras (evidence-value `expected_decision_impact`, counterfactual `projected_effect`) go in a sidecar `cases/<case_id>.trace.json` + the graph Case vertex + the UI — never in the graded answer file**, so they can't perturb README-exact scoring. `affected_txn_ids` is populated from the internal deterministic episode set (`episode_transaction_ids`). Build a **deterministic policy/compliance validator** compiling R1–R10, the §6 stop rules (incl. two-independent-evidence), SAR predicate precedence, action-route constraints, and status transitions — with adversarial unit tests; runs before every emit + write-back. `fraud_probability` is reported **uncalibrated** (README names the field "calibrated"; we do not independently calibrate — a known, declared scoring gap).

4. **P3 agent (~2:30–4:15).** Single Gemini agent ([[0003-single-agent-pydanticai]]): graph tools (card_window, card_txn_history, device_neighbors, region_activity, connected_cards, **transaction_features(TransactionID)** — the metered out-of-graph V-feature fetch), knowledge_search, similar_closed_cases, request_evidence (**frozen, label-blind** simulator per policy §5), write_case. plan→act→observe→pivot under R1–R10 + §6, with **concrete hard caps per case (≤8 agent iterations, ≤20 tool calls, ≤90 s wall, ≤40k tokens)** and a **deterministic finalization on cap-hit** that still emits a valid JSON with `stop_reason="budget_exhausted"`. Exposure = sum of |amount| over `episode_transaction_ids`, **deduped by `TransactionID`**, built deterministically from a published anchor + time window + link rules. Writes the `Case` to a **separate namespace excluded from P1/P2 + eval retrieval** (deterministic Case IDs, idempotent upsert; similar-case retrieval filters the current case). Encodes approval routing + initial-vs-final NBA. **Evidence-value reasoning (innovation):** before each `request_evidence` the agent ranks candidate evidence by expected decision impact — which claim it targets and why it would move the verdict/probability — and logs the chosen request's `expected_decision_impact` **to the trace sidecar**, making the otherwise-required "gather more evidence" step visible and gradeable. **Counterfactual projection (stretch):** if ahead of schedule, each recommended action carries a deterministic `projected_effect` **in the trace sidecar/UI (not the graded file)** — e.g. averted remaining-episode exposure if blocked now vs. customer-friction cost — and the NBA ranking shows the tradeoff; the first thing cut if behind. *`request_evidence` is intentionally P3-only — the agentic treatment effect we measure, not leakage, given the label-blind simulator.*
5. **Run the 20 (~4:15–5:15).** **2-case quota-tested pilot first** (hard per-case call budgets); then P3 on all 20 with throttle/backoff. Validate every file against the schema **and the policy validator**; automated semantic checks on all 20; hand-check 2–3.
6. **P1 + P2 + lift table (~5:15–6:15).** P1 (KB-only, single pass) and P2 (subgraph+KB, single pass) from the same lib, given the **identical raw case input** as P3. **Freeze the scoring/lift spec before running**: fixed held-out eval set of **N=30 closed cases (reducible to 10 under time pressure, equally for all three)**; gold normalization (`confirmed_fraud`/`cleared`→`fraud`/`legitimate`); `uncertain` credited per policy; exposure within a stated tolerance; policy-compliance pass/fail; **lift = (P2−P1) and (P3−P2) on the one common set**. Emit the lift table + token/tool/latency per pipeline.
7. **UI + wrap (~6:15–7:00).** Streamlit dashboard reading the JSON + graph: case list → detail (evidence, structured per-case trace/tool-calls, NBA initial vs final, SAR draft) + P1→P2→P3 comparison. Package repo + brief README.

## Key decisions & tradeoffs
- Three isolated pipelines on one shared model — [[0001-three-isolated-pipelines]].
- Gemini 2.5 Flash, free tier, held constant across P1/P2/P3 — [[0002-gemini-flash-shared-model]].
- Single agent + tools on PydanticAI (not multi-agent) — [[0003-single-agent-pydanticai]].
- Targeted-closure load, prune V-columns, time-local to every scored entity — [[0004-load-targeted-subgraph-prune-columns]].
- Benchmark validity is a first-class concern: split-before-index, held-out cases label-blind across vector **and** graph memory, one common eval set + frozen scoring formula, P3 write-backs namespaced out of retrieval, identical raw input to all three, harness-side token accounting. `request_evidence` asymmetry is the measured agentic lift, not leakage.
- Compliance enforced by a deterministic validator (full R1–R10 + §6 + SAR predicate + routes + status) before emit/write-back, with adversarial tests — not schema validation alone.
- `tokens`/`tool_calls`/`latency_s` are required answer fields, so token efficiency is graded in-file.
- SAR is drafted (narrative + `FILE_REPORT` recommendation + route), never filed externally.
- `fraud_probability` reported uncalibrated (calibration is a known, declared gap).
- Embeddings: all-MiniLM-L6-v2 (local, free). UI: Streamlit.

## Risks / open questions
- **Time.** 6–7 hrs is very tight. Cut-lines: behind at 4:15 → P3-on-20 + schema/policy validation is the committed deliverable (accuracy + NBA + explainability = 60%). Behind at 5:15 → P1/P2 + eval on the reduced N=10 set (same set for all three; report reduced sample explicitly). Behind at 6:15 → minimal read-only JSON viewer instead of the dashboard. P1/P2 and the UI are the declared optional cuts. The **counterfactual `projected_effect`** is a stretch layer, not a committed deliverable — first thing dropped if behind at any checkpoint; **evidence-value reasoning stays** (near-free on top of required behavior).
- **Savanna free-tier limits + cold-starts.** Step 0 smoke-tests first; targeted load stays small; Community Edition is the documented early fallback.
- **Gemini free-tier RPM/RPD** across 20×(up to 3) runs → hard per-case call budgets + 2-case pilot + throttle/backoff; a cheap paid key is the escape hatch.
- **Label leakage** would invalidate the headline lift → mitigated across both vector and graph paths (Step 2) + frozen label-blind evidence simulator.
- **No is-fraud label on the 20** → lift measured on closed cases; the 20 are validated for schema + policy + semantic checks + hand-review, not accuracy.
- **MCP is a REQUIRED component (per the PDF), not a swappable option.** TigerGraph MCP must be wired and demonstrated as the agent's graph interface. The Step-0 adapter keeps direct GSQL as an *internal* dev/reliability layer behind the identical interface (so P3 code is stable if MCP hiccups mid-build), but MCP is the primary, shown integration and the submission uses it.

## Out of scope
- Optional autonomous monitoring beyond the 20 — no time in 6–7 hrs.
- Merchant nodes (no merchant column in the data).
- Real customer/analyst replies (simulated §5); external SAR filing (draft only).
- Independent `fraud_probability` calibration (reported uncalibrated).
- Full per-transaction provenance edge model + first-class evidence/affected-txn graph relations (kept as Case properties + `episode_transaction_ids`); in-graph V-feature subset (fetched via `transaction_features`) — deferred per PLAN-REVIEW-LOG Rounds 1–2.
