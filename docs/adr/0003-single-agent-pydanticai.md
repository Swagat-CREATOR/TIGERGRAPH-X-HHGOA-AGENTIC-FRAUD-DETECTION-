# Single agent with tools (PydanticAI), not multi-agent

P3 (Agentic GraphRAG) is **one** Gemini agent driving a plan→act→observe→pivot loop over a toolset — TigerGraph MCP graph tools, KnowledgeDocument search, case-memory retrieval, controlled evidence-request, and case write-back — emitting a structured Case / NBA / SAR via typed schemas. Framework = **PydanticAI** (native Gemini, native MCP client, per-run token metering, Pydantic structured outputs). PydanticAI + the model client + token meter form the *shared* library that P1/P2 also use (P1: no tools, KB context only; P2: no tools, subgraph+KB context) — the three stay separate code paths per [[0001-three-isolated-pipelines]]; only the model/tool plumbing is shared, not the retrieval or control flow.

**Why (mapped to the PDF's judging basis):** Investigation accuracy + Next-Best-Action are 50% of the score and come from the *quality* of tool use and evidence gathering, not the number of agents. Case summary & explainability (10%) is served directly by typed structured outputs plus our own decision/trace log. Agentic design & engineering (15%) is demonstrated by a clean controlled loop with permission/approval routing and **graph-native** case memory (retrieve similar prior cases from the graph, persist the new case back) — which is more faithful to the PDF than a framework checkpointer. The organizers' explicit emphasis on token efficiency and relative lift favors a lean single agent over multi-agent chatter.

**Deviation from the reference:** the video used three sub-agents (Orchestrator / Fraud Investigator / Report Generator). We collapse to one agent plus an optional final report-formatting pass; the extra LLM round-trips of a multi-agent split cost tokens without buying the accuracy the PDF rewards. Reversible — PydanticAI supports adding delegated sub-agents later if a case type demands it.

**Rejected:** LangGraph (heavier, more scaffolding tokens; graph-native memory removes its main draw), custom thin loop (max control but the most code to own, while PydanticAI already gives exact per-run usage + a native MCP client), full multi-agent (round-trip token cost works against the efficiency dimension).
